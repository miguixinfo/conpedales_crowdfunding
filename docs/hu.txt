Perfecto, aquí vamos a pensar **como producto + backend**, no solo como código. La idea es sacar **todas las funcionalidades en forma de Historias de Usuario (HU)** agrupadas por **épicas**, para que luego podáis planificar sprints fácilmente. 🚴‍♂️🌍

Las separo en **Usuario (público)**, **Admin** y **Sistema**.

---

# 🚴 ÉPICA 1 — Visualización del viaje

Objetivo: que cualquier visitante pueda **entender el viaje Toledo → Atenas y seguir el progreso**.

## HU-1 Ver estadísticas globales

**Como visitante**
quiero ver estadísticas globales del viaje
para entender el progreso total.

**Datos mostrados**

* km recorridos
* km financiados
* desnivel acumulado
* número de etapas
* total donado
* número de donantes

Endpoint:

```
GET /stats
```

---

## HU-2 Ver todas las etapas

**Como visitante**
quiero ver la lista de etapas del viaje
para conocer el recorrido completo.

Datos:

* número de etapa
* país
* origen
* destino
* km
* desnivel

Endpoint

```
GET /stages
```

---

## HU-3 Ver detalle de una etapa

**Como visitante**
quiero ver toda la información de una etapa
para conocer cómo fue ese día.

Datos:

* origen
* destino
* km
* desnivel
* tiempo
* descripción
* fotos
* rutitas

Endpoint

```
GET /stages/{id}
```

---

## HU-4 Ver rutitas de una etapa

**Como visitante**
quiero ver los segmentos de una etapa
para entender qué ocurrió durante el día.

Datos:

* inicio
* final
* km
* desnivel
* eventos

Endpoint

```
GET /segments/stage/{id}
```

---

## HU-5 Ver fotos del viaje

**Como visitante**
quiero ver fotos asociadas a etapas o rutitas
para visualizar la experiencia del viaje.

---

## HU-6 Ver última etapa publicada

**Como visitante**
quiero ver rápidamente la última etapa publicada
para saber el progreso más reciente.

Endpoint

```

```
